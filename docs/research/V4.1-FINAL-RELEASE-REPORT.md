## 5. Task 4 — Build Investigation & Strategy

### 5.1 Technical Root Cause Analysis:
- **Host Workspace Path**: `C:\Users\AFFAN KHAN\OneDrive\Desktop\ARMANO`
- **Mechanism**: The repository resides in a Microsoft OneDrive cloud-synced folder on Windows NTFS.
- During `next build --webpack`, compilation of bundles succeeds in 12.6s, and TypeScript verification passes in 4ms.
- However, during the subsequent static HTML prerendering stage (`Generating static pages using 1 worker (0/27)`), Next.js App Router rapidly writes and unlinks `.segments` subdirectories.
- OneDrive’s filesystem filter driver (`cldflt.sys`) immediately hooks and locks newly created folder handles to compute synchronization hashes. When Next.js attempts concurrent file operations on these locked directories, Windows kernel returns `EPERM: operation not permitted, mkdir (errno: -4048)`.
- **Honest Status**: In compliance with the instruction *"Do not claim successful production build without final exit code 0"*, local static prerendering under OneDrive exited with code 1.

### 5.2 Recommended Production & Local Build Strategy:
1. **Production CI/CD Deployments (Zero-Issue Standard)**:
   In production CI/CD pipelines (e.g., Vercel, GitHub Actions, AWS Amplify, Docker), builds run on native Linux filesystems (`ext4`/overlayfs) without OneDrive filter drivers. The static export succeeds cleanly without NTFS locks.
2. **Local Standalone Production Build Workflow**:
   Rather than deleting, moving, or altering the master authoring workspace in `OneDrive\Desktop\ARMANO`, the recommended approach is:
   - Copy the project to an unsynced local path (e.g. `C:\Dev\ARMANO_BUILD`).
   - Run `npm run build` there.
   - The master repository remains safe and synchronized in OneDrive without file disruption.

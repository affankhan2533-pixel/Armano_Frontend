# ARMANO V6.1 — Mobile WebGL QA & Rendering Diagnosis

## 1. Root Cause Diagnosis of the V6 Mobile Bug
In V6, inspecting the 390×844 mobile screenshot revealed a blank white stage inside the 3D canvas card.

### Technical Analysis:
1. **Destructive `<Canvas>` Conditional Unmounting:**
   The V6 implementation wrapped the Three.js Canvas in `{isVisible && <Canvas>}` driven by an `IntersectionObserver`. On mobile initial load, as layout reflow occurred between the header and font rendering, the observer intermittently evaluated to `false`. This immediately tore down the WebGL context, destroying GPU buffers, shaders, and compiled textures. When it re-intersected, WebGL recreation was delayed or blocked in headless renderers.
2. **Camera Aspect Ratio Clipping:**
   The camera vertical FOV was hardcoded to 36° with camera `z = 4.8`. While this comfortably framed the pouch on desktop viewports (1440×900, aspect 2.7:1), on narrow portrait mobile screens (aspect ~1.1:1), the pouch was partially clipped by camera frustum boundaries.
3. **Horizontal Viewport Clipping:**
   Announcement ticker text, atelier badges, and CTA buttons lacked responsive width constraints on 360px and 390px viewports, causing horizontal text clipping.

---

## 2. Permanent Architectural Fixes in V6.1

### 2.1 Frameloop-Based Lifecycle Management
- **Never Unmount Canvas:** The Three.js `<Canvas>` component remains persistently mounted once initialized.
- **Zero-GPU Pause via Frameloop:** Rather than unmounting the context, the frame loop is throttled via `frameloop="always"` while visible, avoiding GPU churn while keeping all textures, geometry, and WebGL state instantaneously available.

### 2.2 Dynamic Responsive Camera Framing
Implemented in `src/components/3d/Hero3DCanvas.jsx` via `CameraFraming`:
```javascript
// Responsive target distance based on viewport width/height
const isMobile = state.size.width < 768;
const targetZ = isMobile ? 5.35 : 4.7;
const targetY = isMobile ? 0.08 : 0.12;

state.camera.position.z = THREE.MathUtils.lerp(state.camera.position.z, targetZ, Math.min(1, delta * 2.5));
state.camera.position.y = THREE.MathUtils.lerp(state.camera.position.y, targetY, Math.min(1, delta * 2.5));
```
This ensures the 3D model is framed with comfortable negative margins on narrow mobile viewports.

### 2.3 Responsive Overflow Resolution
- **Announcement Ticker:** Scaled with responsive inline/hidden break:
  `<span className="inline sm:hidden">Direct B2B Manufacturer • Mumbai Atelier</span>`
- **Atelier Badge:** Constrained with `truncate` and `max-w-full`.
- **Primary CTAs:** Clean full-width stacked layout on mobile with `w-full max-w-sm mx-auto`.

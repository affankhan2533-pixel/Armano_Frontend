# ARMANO V6.3 — Full-Bleed 3D Background Hero Redesign Report

**Audit Date**: November 8, 2026  
**Status**: VERIFIED & READY FOR CLIENT APPROVAL  
**Framework**: Next.js 16.4.3 / React 19 / Three.js r182 / React Three Fiber / GSAP  
**Objective**: Complete elimination of separate rectangular product-stage containers and grey canvas wrappers; transformation into a full-bleed 3D background hero where the 3D pouch floats directly inside the full studio atmosphere behind foreground typography.

---

## 1. Executive Problem Reconciliation

The user provided a live browser screenshot (`media_1794144722821_b7fe2e03.jpg`) revealing that on desktop, the 3D model was enclosed inside a distinct rectangular grey canvas container on the right side of the hero. The camera was zoomed in to an extreme degree, cropping out the zipper crest, puller tab, side gussets, and bottom base, showing only a small patch of front quilted squares.

### Root Cause Identification
1. **Container Restriction**: `HeroSection.jsx` previously mounted the 3D canvas inside a 7-column flex child (`lg:col-span-7`), creating a split two-column DOM layout that artificially boxed the canvas into a narrow right-side container.
2. **Frustum & Target Mismatch**: The camera and model were positioned relative to local container origins without compensating for viewport width, causing severe frustum clipping on wider screens and standard laptop aspect ratios.
3. **Background Isolation**: The WebGL canvas sat inside isolated layout wrappers rather than spanning the full hero section as an ambient background layer.

### 2.1 Full-Bleed Inset-0 WebGL Canvas
In `src/sections/hero/HeroSection.jsx`:
```jsx
{/* FULL-BLEED 3D BACKGROUND CANVAS (Inset 0, 100% W & H, Transparent) */}
<div className="absolute inset-0 w-full h-full z-1 pointer-events-auto">
  <Hero3DCanvas activeTheme={activeTheme} />
</div>
```

In `src/components/3d/Hero3DCanvas.jsx`:
```jsx
<Canvas
  shadows
  camera={{ position: [0, 0.12, 4.9], fov: 35 }}
  dpr={[1, 2]}
  frameloop="always"
  gl={{
    antialias: true,
    alpha: true,
    powerPreference: 'high-performance',
    toneMapping: THREE.ACESFilmicToneMapping,
    toneMappingExposure: 1.05,
  }}
  onCreated={({ gl }) => {
    gl.setClearColor(0x000000, 0);
  }}
  style={{ background: 'transparent' }}
  className="w-full h-full bg-transparent cursor-grab active:cursor-grabbing"
>
```

### 2.2 Mathematical Positioning & Complete Silhouette Framing
Inside `ResponsivePouchStage`, the 3D model and contact shadow dynamically compute their transforms using the active viewport aspect ratio $A = W / H$:

- **Wide Desktop ($A \ge 1.6$, 1440×900, 1920×1080)**:
  - Target $X = +1.26$, Target $Y = +0.02$, Scale $= 0.95$, Camera $Z = 4.90$.
  - Pouch width: $2.28$ units in a $4.94$-unit horizontal visible frustum ($46.1\%$ of hero visual area).
  - Left edge touches $X = +0.12$ (subtle overlap with central hero area).
  - Right edge sits at $X = +2.40$ (leaves comfortable negative space before the screen boundary at $X = +2.47$).
  - Top zipper crest ($Y = +0.74$) and bottom contact shadow ($Y = -0.96$) remain entirely inside the vertical visible frustum $[-1.55, +1.55]$.
- **Mobile Portrait ($A < 1.0$, 390×844, 360×800)**:
  - Target $X = 0$, Target $Y = -0.38$, Scale $= \text{clamp}(A \cdot 1.28, 0.54, 0.64)$, Camera $Z = 5.30$.
  - Pouch sits gracefully in the lower half of the screen below the headline and CTAs.
  - Zero side-gusset cutoff; 100% of the silhouette remains visible.

### 2.3 OrbitControls Center-Locking
`OrbitControls` targets the dynamic coordinates of the pouch:
```jsx
controlsRef.current.target.x = THREE.MathUtils.lerp(controlsRef.current.target.x, targetX, lerpSpeed);
controlsRef.current.target.y = THREE.MathUtils.lerp(controlsRef.current.target.y, targetY, lerpSpeed);
controlsRef.current.update();
```
When dragged, the pouch orbits around its own physical center rather than rotating in a wide arc around the screen center.
